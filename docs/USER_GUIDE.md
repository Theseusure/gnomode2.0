# Gnomode 2.x — полная инструкция: настройка и работа

Руководство для рядового пользователя команды.  
Репозиторий: [Theseusure/gnomode2.0](https://github.com/Theseusure/gnomode2.0)  
Актуальная ветка с Follow-up и фильтрами buy/transfer: **`feature/followup-ray-filters`**

После запуска UI: [http://127.0.0.1:8000](http://127.0.0.1:8000)

---

## 1. Что это и зачем

Gnomode ищет на **Robinhood Chain** кошельки, которые заходят в новые токены **рано** (низкий market cap), и следит, повторят ли они это на **втором и третьем** новом токене.

**Логика одной фразой:**  
нашли early buyer @ low mcap → положили в таблицу → если взял ещё один **новый** токен снова на низком mcap → Telegram. На высоком mcap — запись есть, алерта нет.

**Правило учёта:** один токен = одна сделка (докупки того же токена не считаются новой сделкой).

### Пять вкладок

| Вкладка | Назначение |
|---------|------------|
| **Настройки** | Фильтры токена и первой сделки (для автопарса) |
| **Скринер** | Живой рынок токенов за ~24ч |
| **Кошельки** | Ручной разбор early buyers по адресу токена |
| **Автопарс** | Автопоиск + Telegram (**источник deal #1**) |
| **Follow-up** | Таблица кошельков + алерты на 2-ю/3-ю сделку |

> Без работающего **Автопарса** таблица Follow-up сама не наполнится — так задумано.

## 2. Что нужно заранее

1. Компьютер или VPS (Windows / Linux / macOS).
2. [Docker Desktop](https://docs.docker.com/desktop/) **или** Python 3.12+ и Node.js (локальная разработка).
3. Telegram-аккаунт.
4. Желательно свой RPC (dRPC / QuickNode) — публичный часто даёт ошибку `429`.

## 3. Установка и запуск

### 3.1. Клон актуальной ветки

```bash
git clone --branch feature/followup-ray-filters https://github.com/Theseusure/gnomode2.0.git
cd gnomode2.0
cp .env.example .env
```

На Linux/macOS:

```bash
chmod +x scripts/*.sh
```

### 3.2. Настройка `.env` (обязательный минимум)

Откройте файл `.env` и заполните:

```env
TELEGRAM_BOT_TOKEN=123456:ABC...     # от @BotFather
TELEGRAM_CHAT_ID=-100...             # ваш чат или группа
# TELEGRAM_TOPIC_ID=123              # только если топик форума

# Рекомендуется при автопарсе:
# RPC_URL=https://YOUR_ENDPOINT...
# RPC_CONCURRENCY=3
```

#### Как получить `TELEGRAM_BOT_TOKEN`

1. Откройте [@BotFather](https://t.me/BotFather).
2. Команда `/newbot` → имя и username бота.
3. Скопируйте токен в `.env`.

#### Как получить `TELEGRAM_CHAT_ID`

1. Напишите своему боту `/start` (или добавьте бота в группу и отправьте сообщение).
2. В браузере откройте:  
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
3. Найдите `"chat":{"id": ...}` — это ваш id.  
   Для супергрупп обычно вид `-100…`.

### 3.3. Запуск через Docker (рекомендуется)

**Непрерывно на ноутбуке** (лучше ловит ATH, не даёт ноутбуку уснуть):

```bash
./scripts/keep-awake.sh
```

На Windows удобнее Git Bash / WSL, либо:

```bash
docker compose up --build
```

Интерфейс: **http://127.0.0.1:8000**

**В фоне:**

```bash
docker compose up -d --build
docker compose logs -f
```

Стоп: `Ctrl+C` или `docker compose down`.

### 3.4. Запуск без Docker (разработка)

**Терминал 1 — API:**

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r backend/requirements.txt
./scripts/dev-api.sh
```

**Терминал 2 — UI:**

```bash
./scripts/dev-ui.sh
```

UI: **http://127.0.0.1:5173** (проксирует `/api` на backend).

Проверка:

```bash
curl http://127.0.0.1:8000/api/health
```

## 4. Первый рабочий день (порядок действий)

Делайте **строго по порядку**.

### Шаг A — Настройки (сетка поиска)

1. Откройте вкладку **Настройки**.
2. Задайте фильтры **токена** (что автопарс вообще смотрит): ликвидность, возраст пары, traders, mcap.
3. Задайте фильтры **первой сделки** (кто считается early buyer):
   - порог mcap входа — обычно **15000**;
   - опционально: баланс ETH, время холда, число токенов за 7 дней.
4. Нажмите **Сохранить**.

> Фильтры 1-й сделки правьте здесь. Сохранение на вкладке Автопарс их не должно затирать.

**Стартовый профиль автопарса (ориентир):**

| Параметр | Значение | Зачем |
|----------|----------|--------|
| Интервал | 5–15 мин | чаще = свежее |
| `max_tokens_per_cycle` | 10–20 на публичном RPC | меньше `429` |
| `min_ath_mcap` | например `50000` | парсить после пампа |
| Порог 1-й сделки | `15000` | «ранний» вход |

### Шаг B — Автопарс (источник сигналов)

1. Вкладка **Автопарс**.
2. Нажмите **Проверить Telegram** — должен прийти пинг. Если нет — см. раздел «Проблемы».
3. Включите расписание **или** нажмите **Запустить сейчас**.
4. Смотрите лог: скринер → hold/qualify (ATH) → парсинг → Telegram.

Пока индекс 24ч прогревается в первый раз, автопарс может подождать — это нормально.

**Сон ноутбука:** ATH пишется только пока процесс жив. Уснули в момент пампа — пик могли не увидеть. Для 24/7 на ноутбуке используйте `keep-awake.sh` или отключите sleep; на VPS проблемы сна нет.

### Шаг C — Follow-up (таблица + алерты 2/3)

1. Вкладка **Follow-up**.
2. Включите **Ingest** (автопарс → таблица).
3. Выставьте фильтры алертов (см. раздел 5).
4. Включите **Команды бота**, если хотите управлять из Telegram (`/help`).
5. **Сохранить** → **Follow-up Вкл** → при желании **Запустить сейчас**.
6. Нажмите **Проверить Telegram** и на этой вкладке.

Когда автопарс успешно отправит early buyers, в таблице появятся кошельки со статусом `watching` и deal **#1**.

## 5. Как пользоваться каждой вкладкой

### Настройки

Здесь живёт «кто нам интересен на первой сделке».  
Меняете фильтры → **Сохранить** → автопарс подхватывает.

### Скринер

- Смотрите живой список токенов.
- Фильтруйте по liq / age / traders / mcap.
- Можно перенести адреса во вкладку **Кошельки** для ручного разбора.
- Honeypot-отсев через GMGN.

### Кошельки (ручной режим)

1. Вставьте адрес токена.
2. Запустите поиск early buyers (кто купил до порога mcap).
3. Смотрите лог, CSV, ссылки GMGN / Blockscout.

Это **ручной** разбор. В Follow-up кошельки попадают не отсюда, а из **Автопарса** (после успешного Telegram).

### Автопарс

Цикл:

1. Скрининг по фильтрам из Настроек.
2. ATH-гейт: ниже порога → hold, выше → qualify.
3. Парсинг early buyers.
4. Дедуп (кошелёк+токен уже слали — не шлём снова).
5. Telegram → затем Follow-up ingest (deal #1), если Ingest включён.

Кнопки: вкл/выкл, интервал, лимиты, стоп, сброс счётчиков, очистка дедупа, тест Telegram, лог.

### Follow-up

| Этап | Смысл |
|------|--------|
| Deal #1 | Из автопарса после успешного Telegram |
| Deal #2/#3 | Опрос кошелька (Blockscout) на новые токены |
| Алерт | Только #2/#3 + low mcap + фильтры buy USD |
| Высокий mcap | Пишем в таблицу, **без** Telegram |
| `done` | Набрали `max_deals` (обычно 3) — больше не следим |

#### Рекомендуемые фильтры Follow-up

| Фильтр | Значение | Смысл |
|--------|----------|--------|
| Max mcap алерта | `15000` | алерт только на низком mcap |
| Min mcap | пусто | без нижней границы |
| Min / Max buy USD | по вкусу или пусто | размер покупки |
| buys_only | **вкл** | только покупки с DEX |
| track_transfers | **выкл** | не считать EOA-переводы сделками |
| Интервал | `300` сек | опрос раз в 5 минут |
| Ingest | **вкл** | брать deal #1 из автопарса |
| Max сделок | `3` | после 3-го токена статус `done` |

#### Кнопки вкладки Follow-up

| Элемент | Зачем |
|---------|--------|
| Follow-up Вкл | Фоновый цикл опроса |
| Ingest | Автопарс добавляет кошельки в таблицу |
| Команды бота | `/status`, `/filters`, … из Telegram |
| buys_only / track_transfers | Какие события считать сделкой |
| Max/Min mcap, Min/Max buy USD | Фильтры алерта |
| Telegram chat / topic | Переопределение `.env` |
| Сохранить | Запись конфига |
| Запустить сейчас | Внеочередной цикл |
| Стоп | Прервать текущий цикл |
| Проверить Telegram | Тестовое сообщение |
| Сброс счётчиков | Обнулить лог/счётчики (таблица не чистится) |

#### Колонки таблицы

| Колонка | Смысл |
|---------|--------|
| Адрес | Ссылка на GMGN |
| Статус | `watching` — следим; `done` — набрали лимит сделок |
| Сделок | Сколько разных токенов учтено |
| Баланс ETH | На момент попадания в таблицу |
| Токенов 7д | Активность на момент ingest |
| 1-й mcap | Mcap первой сделки |
| История | `#N SYMBOL @mcap $buy ✓` — галочка = алерт уже ушёл |

## 6. Telegram-бот Follow-up

Тот же бот, что в `.env` (`TELEGRAM_BOT_TOKEN`). Пишите в том же чате, что указан в конфиге.

| Команда | Пример | Действие |
|---------|--------|----------|
| `/help` `/start` | `/help` | Справка |
| `/status` | `/status` | Статус цикла |
| `/wallets` | `/wallets` | Список watching |
| `/filters` | `/filters` | Текущие фильтры |
| `/on` `/off` | `/on` | Вкл/выкл Follow-up |
| `/run` | `/run` | Цикл сейчас |
| `/set_max_mcap` | `/set_max_mcap 15000` | Max mcap |
| `/set_min_mcap` | `/set_min_mcap off` | Min mcap |
| `/set_min_bought` | `/set_min_bought 50` | Min buy $ |
| `/set_max_bought` | `/set_max_bought off` | Max buy $ |
| `/set_buys_only` | `/set_buys_only on` | Только DEX buys |
| `/set_transfers` | `/set_transfers off` | EOA transfers |
| `/set_interval` | `/set_interval 300` | Интервал сек |

## 7. Когда приходит алерт и когда нет

**Приходит**, если всё сразу:

- номер сделки 2 или 3;
- mcap известен и ≤ Max mcap (и ≥ Min, если задан);
- сумма покупки проходит Min/Max buy USD (если заданы);
- Telegram настроен;
- по этой паре кошелёк+токен ещё не слали.

**Не приходит** (но сделка может сохраниться):

- deal #1 (это discovery);
- высокий mcap;
- mcap неизвестен;
- задан Min buy USD, а сумму оценить не удалось;
- событие не buy с DEX при `buys_only`;
- кошелёк уже `done`.

## 8. Типичный рабочий сценарий «как искать»

1. **Настройки** — порог раннего входа `15000`, разумные фильтры токена.
2. **Автопарс Вкл** + проверка Telegram.
3. **Follow-up** — Ingest + Max mcap `15000` + Вкл.
4. Ждёте: в Telegram приходят early buyers → в таблице Follow-up появляются `#1`.
5. Когда тот же кошелёк берёт **другой** токен на низком mcap — отдельный алерт `#2` / `#3`.
6. Смотрите адрес в GMGN и решаете, торговать или нет.

Скринер и вкладка Кошельки — для ручного доразбора; для автопотока не обязательны.

## 9. Проблемы и решения

| Симптом | Что проверить |
|---------|----------------|
| Follow-up таблица пустая | Автопарс работает? Telegram из автопарса уходит? Ingest включён и нажато Сохранить? |
| Нет алертов на #2/#3 | Follow-up Вкл? В истории есть #2/#3? Mcap ≤ порога? Не режет Min buy USD? |
| Автопарс 0 кошельков | Слишком жёсткие фильтры 1-й сделки; или цена уже выше порога mcap |
| `chat not found` / `401` | Бот не в чате / неверный токен / для группы нужен id `-100…` |
| Бот не отвечает на команды | Команды бота включены? Пишете из того же chat id? Один процесс на токен? |
| RPC `429` | Свой `RPC_URL`, снизить `RPC_CONCURRENCY` и `max_tokens_per_cycle` |

---

## 10. Ограничения (важно понимать)

1. Deal #1 появляется **только** из автопарса после успешного Telegram + Ingest.
2. Mcap на #2/#3 при опросе — **текущий** с DexScreener, не исторический в секунду покупки.
3. Это EVM-фильтры в духе RayBot (buy / transfer / mcap / USD), не полный Solana RayBot.
4. RayBot **не обязателен** — свой Telegram-бот уже встроен.
5. Опрос смотрит ограниченное число страниц Blockscout; у сверх-активных кошельков редкий токен можно пропустить.
